# DLLs the shipped Windows runtime is allowed to expect from the host.
#
# The rule is the same one encoded for Linux in host-provided-libs.txt: every
# DLL a plugin imports must either be shipped inside the addon or be listed here
# because every supported Windows already provides it.
#
# This list is not guesswork. It was produced by reading the PE import tables of
# every DLL in a working Windows runtime tree:
#
#   llvm-objdump -p <plugin>.dll | Select-String '^DLL Name:'
#
# Over all 407 plugin DLLs the only import satisfied from inside the runtime was
# libvlccore.dll; everything else was one of the names below.
#
# Deliberately NOT listed, because they are toolchain runtimes rather than
# Windows components and therefore MUST ship inside the addon:
#
#   libgcc_s_seh-1.dll
#
# A mingw-built runtime imports it (libx265_plugin, the srt access plugins and
# libgme_plugin all do) and no Windows installation provides it. Leaving it out
# of the package is the exact failure this project already hit on Linux, where
# plugin modules depended on libraries that were never shipped. It is declared
# in the gdextension manifest instead, so the assembler refuses to build a
# package that omits it.
#
# Matching is case-insensitive, as Windows DLL resolution is.
